# 高频量化交易与订单执行系统项目计划书

## 一、项目概述

本项目面向专业交易员、量化研究员与量化交易团队，建设一套支持多市场、多品种的高频量化交易与订单执行系统。系统覆盖实时行情接入、低延迟订单执行、策略回测、金融数据中台、风控拦截与 Web 端实时交易工作站，目标是在高频行情推送和高并发下单场景下，提供稳定、低延迟、可观测、可扩展的交易基础设施。

项目将基于当前 `trading-system` 原型继续建设。现有仓库已具备 Go 撮合引擎、订单簿、WebSocket 服务、ClickHouse 初始化脚本、Postgres 订单与成交表、Prometheus 指标与部署雏形，可作为后续工程化迭代基础。

## 二、建设目标

- 构建低延迟 Go 后端交易执行网关，完成订单接入、校验、路由、撮合/转发、执行回报与指标采集。
- 建设实时行情网关，实现交易所行情 API 对接、毫秒级解码、标准化分发与 WebSocket 推送。
- 搭建专业级 Web 交易终端，支持 K 线、盘口、逐笔成交、订单管理、账户状态与策略监控。
- 建设金融数据中台，使用 ClickHouse/TimescaleDB 存储 TB 级 Tick、K 线、订单流与执行回报数据。
- 建设策略回测框架，支持统计套利、做市等策略的历史数据回放、撮合模拟、绩效分析与参数评估。
- 建设事前/事中风控模块，在核心交易链路中拦截异常订单、超限风险与策略失控行为。

## 三、核心建设内容

### 1. 后端低延迟交易引擎

后端采用 Go 作为核心开发语言，重点建设极速交易执行网关、内部订单流转管线、撮合/路由模块和执行回报模块。

关键实现包括：

- 使用 RingBuffer 无锁数据结构优化订单、行情、执行回报在内部模块间的流转，降低锁竞争和 GC 抖动。
- 将核心链路拆分为订单接入、风险检查、撮合/路由、执行回报、持久化与推送等阶段。
- 对接交易所 REST/WebSocket API，实现行情订阅、订单提交、撤单、成交回报与连接重试。
- 对价格、数量、订单类型、TIF、账户、品种等字段进行标准化建模。
- 建立 Prometheus 指标体系，覆盖订单接入量、撮合延迟、队列积压、错误率、交易所响应耗时等指标。

### 2. 实时行情网关

行情网关负责多市场、多品种行情接入、标准化、聚合与分发。

关键实现包括：

- 对接交易所 WebSocket 行情流，支持 Tick、Order Book、Trade、Kline 等数据类型。
- 将不同交易所行情字段标准化为统一内部事件模型。
- 对高频行情采用增量推送，避免全量刷新造成网络与前端压力。
- 支持断线重连、订阅恢复、乱序检测、数据延迟监控与异常告警。
- 将核心行情数据写入 ClickHouse/TimescaleDB，为回测和分析提供数据基础。

### 3. Web 实时交易终端

前端采用 React + TypeScript 从零搭建专业级 Web 交易工作站，通过 WebSocket 与后端保持全双工通信。

核心功能包括：

- 实时 K 线、分时、逐笔成交、深度盘口与订单簿展示。
- 集成 TradingView/ECharts，并结合 Canvas 渲染高频 Order Book 与成交流。
- 使用虚拟列表、增量渲染和节流策略处理高频数据推送下的前端性能问题。
- 支持下单、撤单、批量撤单、订单状态跟踪、成交回报、账户资产和持仓查看。
- 支持策略运行状态、风控拦截记录、延迟指标和系统健康状态展示。
- 建立 WebSocket 断线重连、消息序列校验、前端降级渲染与异常提示机制。

### 4. 金融数据中台

数据层采用 ClickHouse/TimescaleDB 存储海量金融时序数据，并保留 Postgres 作为订单、账户、配置等事务型数据存储。

核心数据范围包括：

- Tick 行情、逐笔成交、深度快照、增量盘口。
- K 线聚合数据，包括 1s、1m、5m、1h 等周期。
- 委托订单、成交记录、执行回报、撤单记录。
- 策略信号、风控事件、账户资产、持仓快照。
- 回测任务、参数配置、回测结果与绩效指标。

数据中台需支持秒级聚合查询，为策略回测、盘后分析、风控复盘和交易终端图表提供统一数据服务。

### 5. 策略工程化与风控

项目将配合量化研究员完成统计套利、做市等策略的工程化落地。

策略工程化包括：

- 定义统一策略接口，支持行情输入、信号输出、订单生成、状态管理和参数配置。
- 支持策略沙盒运行，隔离策略异常对核心交易链路的影响。
- 支持历史行情回放、模拟撮合、手续费/滑点建模和绩效分析。
- 提供策略监控面板，展示收益、回撤、成交率、撤单率、持仓、风险暴露等指标。

风控模块包括：

- 事前风控：账户权限、品种白名单、单笔金额、单笔数量、价格偏离、最大持仓、最大杠杆。
- 事中风控：订单频率、撤单频率、成交异常、亏损阈值、盘口冲击、策略熔断。
- 风控结果进入执行链路，支持拒单、降频、只撤不下、策略暂停和人工确认。
- 风控事件需完整落库，并推送到 Web 终端和监控系统。

## 四、系统接口与数据契约

### 后端核心接口

- `POST /api/v1/order`：提交订单，包含账户、品种、方向、订单类型、价格、数量、TIF、客户端订单号。
- `POST /api/v1/order/cancel`：撤销订单，支持按系统订单号或客户端订单号撤单。
- `GET /api/v1/orders`：查询订单列表，支持账户、品种、状态、时间范围过滤。
- `GET /api/v1/trades`：查询成交记录。
- `GET /api/v1/market/kline`：查询 K 线数据。
- `GET /api/v1/market/depth`：查询盘口深度快照。
- `GET /api/v1/risk/events`：查询风控事件。
- `WS /ws`：推送行情、订单状态、成交回报、策略状态和系统指标。

### WebSocket 消息类型

- `market.tick`：实时 Tick。
- `market.depth.snapshot`：盘口快照。
- `market.depth.delta`：盘口增量。
- `market.trade`：逐笔成交。
- `order.accepted`：订单已接收。
- `order.rejected`：订单被拒绝。
- `order.filled`：订单成交。
- `order.cancelled`：订单撤销。
- `risk.blocked`：风控拦截。
- `strategy.status`：策略状态变化。
- `system.metric`：系统延迟、队列积压、连接状态等指标。

## 六、验收标准与测试计划

### 性能验收

- 订单核心链路在目标压测环境下达到毫秒级处理延迟。
- 行情解码与 WebSocket 分发在高频推送下保持稳定，无明显堆积。
- 前端 Order Book、逐笔成交和 K 线在高频推送下保持流畅。
- ClickHouse/TimescaleDB 支持 TB 级 Tick 数据的秒级聚合查询目标。

### 功能测试

- 限价单、市价单、IOC、FOK 等订单类型测试。
- 下单、撤单、成交、部分成交、拒单、风控拦截全流程测试。
- 行情订阅、断线重连、订阅恢复、乱序和重复消息处理测试。
- Web 终端实时刷新、订单状态同步、图表查询和异常提示测试。
- 策略回测、模拟撮合、绩效计算和参数配置测试。

### 稳定性测试

- 高频订单压测。
- 高频行情推送压测。
- WebSocket 长连接稳定性测试。
- 数据库写入和聚合查询压力测试。
- 交易所连接中断、超时、限流和返回异常测试。
- 风控熔断和策略暂停测试。

## 七、风险与应对

- 低延迟目标风险：通过 RingBuffer、对象复用、减少跨 goroutine 共享状态、压测基线和指标观测持续优化。
- 交易所 API 差异风险：建立统一适配层，将交易所差异隔离在 gateway 模块。
- 高频数据前端卡顿风险：使用 Canvas、虚拟列表、增量渲染、批量更新和降频展示策略。
- 海量数据查询风险：通过 ClickHouse 分区、物化视图、预聚合和冷热数据分层降低查询压力。
- 策略失控风险：在订单进入核心链路前后加入风控拦截、熔断和人工接管机制。
- 生产稳定性风险：建立监控、告警、日志、审计、故障演练和回滚方案。

## 八、默认假设

- 本计划书按“内部立项”用途撰写，兼顾技术评审所需的架构和验收内容。
- 项目基于当前 `trading-system` 仓库继续建设，不作为完全从零启动项目。
- 后端核心语言采用 Go，前端采用 React + TypeScript。
- 时序数据优先采用 ClickHouse，TimescaleDB 可作为补充或替代方案。
- 首期目标先接入一个交易所和若干核心交易品种，再扩展到多市场、多品种。
- 首期策略以统计套利和做市策略为重点，后续扩展更多策略类型。
